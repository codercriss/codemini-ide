### Added

### Source Control: Push is now one real push
- **Push no longer makes one GitHub commit per file.** It used to walk the whole committed tree and write every file through GitHub's Contents API, so a push of 40 files showed up as 40 commits titled "Update <path> via CodeMini", your own commit messages never arrived, and a failure midway left GitHub half-updated. It now works like `git push`: it uploads the file contents GitHub does not already have, builds a tree and a commit for each local commit being sent (with that commit's own message, and its author and date when it has a real identity), and moves the branch with a single, non-forced update at the very end. Until that last step nothing on GitHub has changed, so any failure (network, rate limit, a branch that moved under you) leaves the remote exactly as it was, and the message says so. Requests are made one at a time, as GitHub asks for writes.
- **Only what changed is sent.** The remote's file list is compared by git blob id (computed here, checked against `git hash-object` in the tests), so a file that is already up there unchanged is never uploaded again, and content GitHub already holds under another path (a copy or rename) is referenced instead of re-uploaded. Pushing with nothing new now reads from GitHub and writes nothing, and says "Nothing to push".
- **Deleting a file locally and pushing now deletes it on GitHub.** Only files removed since the last push are deleted; a file that is on GitHub but was never known to this workspace is left alone, and a file someone else already removed is not an error.
- **Which commits go up.** The last local commit pushed or pulled for each remote branch is now remembered (a new `synced_<branch>` record, trusted only for the repository it was recorded against). The next push sends the commits after it, oldest first. Merge commits go up as the single commit they are (the remote history is linear; a merged-in branch arrives through its merge commit). Into an empty repository the whole history is sent: the first file is written through the Contents API (GitHub accepts nothing else in a repository with no commits), then the rest goes up normally. The first push to a repository that already has commits, and a push after history was rewritten here (rebase, reset, amend), go up as ONE commit holding the current tree, using the tip's message; the result line says so. Mode bits (an executable stays executable) and binary files are preserved.
- **A push to a branch that does not exist on GitHub is refused** with a plain message instead of creating it. A repository GitHub cannot find (or the token cannot see) is reported as such. If GitHub reports the file list as too large to compare, files still go up but deletions are skipped, and the result says so.
- **Remote tab: a note above the buttons says what Push will send**, e.g. "Pushes the last commit on **main** (3 uncommitted changes not included).", "Pushes the 2 commits on **main** since the last push.", or "Nothing new to push". Uncommitted changes, staged or not, are never sent, and the help text now says so.
- **Fixed: the unpushed-commit count never went down.** The `↑N` badge in the status bar, the Remote tab's "N local commits not yet pushed", Fetch's result line and the Pull warning counted from GitHub's own commit id, which does not exist in the local commit store, so every commit always counted as unpushed (even right after a push). They now count from the last synced local commit. A repository that was last pushed before this version still shows every commit until its next push.
- Known limits (unchanged): auth is still a personal access token, there is one remote, no force push, and a push does not check whether someone else changed the same files on GitHub since your last fetch (a non-fast-forward is refused, but a newer commit on top of the one you saw is built upon, so the same file is overwritten). Tags are not pushed. Needs the same token scopes as before (`repo`, plus `workflow` for workflow files).
- New `tests/git-push.test.js` (40 checks, run for real against a fake GitHub that is strict about what the Git Data API accepts: missing blobs, deleting an absent path, non-fast-forward updates, the Contents API on a non-empty repository). Covers the plan (incremental, full, squash, merges), commit messages and order, deletions, binary files and modes, authorship, empty repositories (404 and 409 variants, and a repository that refuses an explicit branch), failures leaving GitHub untouched, a branch moving mid-push, the synced record, the unpushed count and the Remote tab note. Checked by breaking the code 18 ways and watching a test fail each time.

### Workspaces: a full audit of how the app adapts to them
Every workspace has its own isolated database, and a file's id only exists in one of them. A lot of code picked "the" database the wrong way (the window's outer database instead of the open one), which showed up as things silently not saving, appearing in the wrong place, or vanishing.

- **Typing in a Document inside a workspace never saved.** A Document works out where to save from the window record, which always names the OUTER database; the file only exists in the workspace's own one, so the save found nothing and quietly did nothing. File tabs now remember the database their file was opened from, and every save (Documents, code, notebooks) goes there.
- **Edits could be lost when moving between a workspace and CodeMini with a tab open.** The save looked the file up in whichever database happened to be open by then. Now, when the open database changes, unsaved edits are first saved to the database each tab belongs to and those tabs are closed (a tab only works against its own database), with a short notice.
- **Saving could create databases.** A save, search, restore or terminal command aimed at a workspace that had been deleted re-created it as an empty "ghost" database (and could block deleting it again). Those paths now open a database only if it exists.
- **Back/Forward across a workspace boundary showed the wrong files.** They restored the folder path without switching database, so a workspace's name appeared over the outer database's files (or the reverse). They now switch database first, and a workspace that has been deleted falls back to CodeMini.
- **Cut/Copy/Paste across databases.** The clipboard recorded the window's outer database as its source and Paste wrote to it, so pasting inside a workspace sent files to the outer database (invisible), and pasting between a workspace and CodeMini was treated as a same-database paste. Cross-database "cut" also never removed the original. Fixed all three; tabs of files that were moved out are closed.
- **Global search searched the outer database** even inside a workspace, and leaked a connection each search. It now searches the open database and closes the connection.
- **Recycle bin restore put files in the wrong database.** Restoring something deleted inside a workspace (from CodeMini, or another workspace) wrote it into the open database as an orphan and removed it from the bin. Deleted items now remember where they came from and are restored there; anything whose workspace no longer exists stays in the bin with a message instead of being dropped.
- **Creating a workspace:** it left a database connection open for the rest of the session (blocking deleting it), saved the new workspace into the wrong database if you were inside another workspace (so it never appeared), and allowed two workspaces with the same name. Fixed.
- **Deleting a workspace** now also forgets its saved trust decision and drops its recycle-bin entries.
- Checked and found fine: Source Control (keyed per database), the terminal following the Explorer into a workspace, workspace rename, window deletion cleaning up workspace databases, Workspace Trust prompting on open.

### Changed
- **Isolated Console: Stop really stops a running command.** Until now the Stop button only printed "[Execution Interrupted]" and did nothing else. With Isolation on, a command running on the runner's host (a never-ending `await`, a Python `ainput()` nobody answers, a long job) is now ended by shutting that host down. The command's own block says "[Execution Interrupted]" (not an error, and it never falls back to the in-app engine) and the next command starts a fresh host, so the window's JavaScript variables and Python namespace are reset (the Terminal of that window shares the host, so its state is reset too). In Normal mode Stop behaves as before, because code running inside CodeMini cannot be interrupted from outside. A tight synchronous loop can still freeze a browser that keeps the runner frame in the same process as the app; this needs the page to stay responsive.
- **The editor's Run button and the bottom Console's input field now run on the runner's host** when Isolation is on for the Console (they follow the Console setting). Before, a `.js` file was evaluated with `eval.call(window, ...)` in the app's own global scope, and Python, PHP and Ruby ran in engines loaded into the app page. The code now shares the per-window host with the Console and the Terminal; the bottom panel's Stop button shuts that host down (the run reports "[Execution Interrupted]"); output is printed live; Normal mode and the fallback (runner unavailable, with the one-time note) keep the in-app engines.
- **The editor's Debug now runs on the host too** (JavaScript and Python; it follows the Console setting). Its log is built from escaped host text, and its Variables panel reads the host's variables (Python with the Console's own snippet, JavaScript from the host's globals) and escapes every name and value; opening the panel never starts a host. Normal mode and the fallback keep the in-app path. Differences from before: Debug has no Stop (closing the window ends a runaway run), a top-level `return` in a debugged JavaScript file only works together with `await`, and "Returned:" shows the last expression's value.
- **Python notebook cells now run on the runner's host** when Isolation is on for Notebooks (Settings > Security > Notebooks, which was a disabled placeholder; it follows the global mode unless overridden). They share one Python session with the Console, Terminal and editor Run of the same window. Interrupt really ends a running cell (it shuts the host down; the cell says so and that the variables were reset), Restart and Run All start a fresh Python session on the host, the Variables Explorer reads the host (every name and value escaped), `!pip install` and the package manager install inside the host, `ainput` and `input()` work, and plots, `%time` and the other magics are kept. Differences from Normal mode: HTML sent with `display_html` is always sanitized (scripts in it do not run), and a stop of the Console/Terminal/Run of that window also resets the notebook's Python.
- **The Python notebook scratchpad runs on the host too** (same setting, and the same Python session as the cells of that window). Its output is shown exactly as before (text, filtered plot images), `display_html` is not shown there, and it still has no Stop.
- **SQL notebook cells, their scratchpad, the SQL Variables Explorer, Restart and Run All now run on the host too** (a new host language `sql`: sql.js is loaded inside the runner, one database per window, with the same helper functions as before). The result sets come back as JSON, are validated and escaped field by field (the old in-app renderer only escaped `<`, so text such as `&lt;b&gt;` is now shown literally); BLOBs are shown as their bytes as before; a result over about 1 MB is cut with a note; for ordinary data the table markup is identical in both modes. Interrupt can end a long query only while the page stays responsive (the engine is synchronous). **The runner project must be redeployed** (`runner/exec.js` changed); against an older runner a SQL cell says so and tells you to redeploy or set Notebooks to Normal.
- **R notebook cells and their scratchpad now run on the host too** (a new host language `r`: webR is started inside the runner, which has no cross-origin-isolation headers, exactly like the app, so it uses the same fallback channel as before). Cells use one R environment per window and the scratchpad R's global environment, as before; plots come back as base64 through the same filter; `library(x)` packages are installed on the host (auto-install) and the package manager installs there too; Restart and Run All give a fresh environment. R cannot be interrupted except by shutting the host down (Interrupt does that while the page stays responsive). **The runner project must be redeployed**; against an older runner an R cell says so. With this, no notebook code runs in the app unless Normal mode is chosen (the code formatter only parses).

## 1.3.2

### Fixed
- **Dialogs showed the previous dialog's message.** All the small dialogs share one popup. Its message line only cleared when the next dialog had a message, because the code that hides it had been swallowed by a trailing `//` comment on the same line. So New Python/R/JS file, New Document and the other dialogs without a message showed whatever the last dialog said ("Enter repository (e.g., facebook/react):", "Are you sure you want to permanently delete this cell?", "Are you sure you want to close window ...?"). The message is now cleared and hidden when a dialog has none.
- **Console: Trusted/Untrusted could not be switched back.** The Console handles the toggle itself, but the notebook's page-wide `.tb-trust` handler also ran on it and toggled the button a second time (and, in Restricted Mode, refused to trust). The label and the saved state drifted apart, and the wrong state was saved, so it survived closing and reopening the Console. That handler now ignores Consoles.
- **Console: Variables Explorer refresh replaced the Console's list with the notebook's.** The Console reuses the class names `.tb-vars`, `.vars-refresh` and `.vars-close`, so the notebook handlers also ran on it. Refresh asked the in-app Python for its variables (loading Pyodide, even for a JavaScript, PHP or Ruby Console) and wrote them over the Console's own list. Those handlers now ignore Consoles.
- **Archive viewer: "Extract all" threw `fileData is not defined`.** The viewer never kept the archive's record. It now does, and extracts into the folder the archive lives in (as its comment always said) instead of whichever folder the Explorer was showing. The Explorer's folder is only the fallback.
- **SQL notebooks: "Copy table" copied only the header.** `querySelectorAll('th', 'td')` takes one selector list, so the data cells were dropped and every data row came out blank. It is now `'th, td'`.
- **Explorer dates: "Yesterday" was wrong after midnight.** The label counted elapsed 24-hour blocks, so a file saved at 23:30 two days ago was "Yesterday" for most of today. It now compares calendar days.
- New test: `tests/e2e/regressions-1-3-2.e2e.js` (29 checks, 16 of them fail on the 1.3.1 code, at least one per fix above).

### Security
- **Console and Terminal code can run on the runner (phase 2, IN PROGRESS: see docs/RESUME.md).** A new hidden execution host (`runner/exec.html`, `runner/exec.js`, one per window/profile) runs JavaScript, Python, PHP and Ruby typed into the Console, and the Terminal's `js`, `python -c`, `php -r`, `ruby -e` and script-file runs, on the runner's origin, so that code cannot read the app's storage or call its functions (it also no longer has CodeMini's DOM). The app sends `{lang, code}` and renders the structured output with the same HTML as before (escaped; `display_html` is sanitized). New settings **Settings > Security > Console / Terminal** (Use global / Isolated / Normal); Notebooks are still not covered. Automatic fallback to the in-app engines, with a one-time note, when the host cannot be reached (including when only `exec.html` is missing because the runner was not redeployed; that failure is remembered separately and does not affect preview isolation). Behaviour changes: in Isolated mode the Console's Python no longer shares its interpreter with notebooks, and the Console's JavaScript can no longer touch CodeMini's DOM. Fixed on the way: an `await` command that failed at runtime was run a second time; the Terminal's `js` error message and file-run errors were interpolated into HTML unescaped; a command that finished with an error was reported as a failed request (`[object Object]`). Verified in a browser: the JavaScript Console path (real engine); Python/PHP/Ruby only with stand-in engines (the sandbox had no network); **the Terminal path is NOT yet verified in a browser** (see docs/RESUME.md).
- **Preview gear menu**: the Isolation group is now separated from the group above by a rule and spacing (it used to sit directly under the last radio).
- **Fixed, preview: reloading while you type did not update pages that link other files.** Auto-reload re-rendered the page from a raw database record, which has no `absolutePath` until the path tree is built, so resolving its relative `<link>`/`<script>` threw and the preview silently stopped updating (it existed before the runner: the pre-runner build behaves the same). The page is now found by id. Renders also run one at a time, keeping only the latest request, so overlapping updates cannot trample the shared URL table (more likely now that minting is asynchronous).
- **Fixed, preview: the Storage Manager and the page broke after an in-place rewrite (Legacy strategy).** The helper script that virtualises the page's storage ran a second time in the same window and wrapped its own wrapper (`Illegal invocation`, empty Storage Manager). It now installs once per window.
- **Fixed, preview: "open in external browser" works while isolated.** The pop-out opens a runner page of its own (still a separate origin, `window.opener` removed) and the runner re-makes the page's files there, rewriting the references between them. Normal mode keeps its previous behaviour.
- **Fixed, preview console: the input was less than half the row's width** (169 px in a 360 px row): the prompt's wrapper element was never closed, so the input was not a child of the flex row. It now fills the row.
- **Factory Reset and Delete Profile also clear data previews keep in the runner** (it lives in the runner's origin now, out of the app's reach); a hidden runner frame does it when no preview is open.
- **Isolated previews (phase 1).** Live Preview now runs the previewed page on a separate origin, the new **preview runner** (`runner/`, its own Vercel project, `https://the-code-mini-runner.vercel.app`; deployment steps in `runner/README.md`). A previewed page can no longer read the app's storage (vault, token record, device key), call its functions, or fetch its files. The runner mints the page's `blob:` URLs and relays the console, network, inspector and reload traffic, so those tools work as before. If the runner is unreachable the preview falls back to the previous same-origin mode and the toolbar shows an amber warning (green shield when isolated). `codemini_runner` = `off` switches it off; `codemini_runner_url` overrides the address on localhost only; a runner on the app's own origin is refused. Pop-out is unavailable while isolated. The terminal, Console and notebooks are not yet covered (later phases).
- **Isolation is now a setting** (Settings > Security > Isolation): a global **Isolated (recommended) / Normal** choice, with a per-surface override. Live Preview has one today (Use global / Isolated / Normal, also in the preview's gear menu, kept in sync with Settings); Console, Terminal and Notebooks are shown disabled as "not yet available" so the control exists before the feature does. Changes apply at once and rebuild an open preview. Default is Isolated. `codemini_runner` = `off` still forces Normal everywhere. The status bar indicator moved to the far right, after the file name.
- **Isolated previews keep both reload strategies.** "Full Navigation" works as before. "Legacy (in-place rewrite)" now also works while isolated: the runner shell, which shares the page's origin, rewrites the page in place (state kept) and navigates instead when nothing is showing yet.
- **Fixed: the in-place rewrite always crashed the page's injected helper script** (`Identifier 'lastErrorTracker' has already been declared`, in the original same-origin mode too), which also left the console, network and inspector relay dead after a rewrite. The helper's top-level `let`s are now `var`, and its console/fetch/XHR patches are installed once per window, so a rewrite no longer throws or logs twice.
- **Isolation status is now readable on a phone.** Tapping the shield (or the warning icon) opens a note inside the preview with the status, the reason for any fallback, the runner address and the app origin, with Retry and Close; it also opens once on its own the first time isolation falls back. (It used to use a toast that sat under the full-screen preview.) The shell now reports a page as loaded only once the frame really shows it, and the reasons for falling back are specific.
- The app's `vercel.json` now sends `X-Content-Type-Options: nosniff`, `frame-ancestors 'self'` and a referrer policy; `.vercelignore` keeps `runner/` out of the app deployment.
- New tests: `tests/runner.test.js` (the shell and client against fake windows: origin allowlist, handshake and nonce, relay envelope, spoofing attempts, fallback timing) and `tests/e2e/runner.e2e.js` (two real origins in Chromium: the page works, cannot reach the app's storage, functions, files or databases, forged messages are ignored, refresh works, another site cannot embed the runner, and the fallback, off and misconfigured cases).
- **File names could run script (fixed).** A name like `<img src=x onerror=...>` in a zip you opened, a repo you cloned or a file you imported was put into the page as HTML in the Explorer (including its tooltip), search results, tab titles, the breadcrumb, the archive viewer (where a quote also broke out of `data-entry-path`), the Stacks panel, the terminal's `ls`, `find` and `tree`, toasts, context menus and dialogs. All now go through the new shared `CodeMiniEscape` (`js/core/html-escape.js`), or `textContent`. Dialog text is now plain text.
- **Markdown, documents and saved output are allowlisted.** Notebook Markdown cells, the Markdown preview, the document editor (`.docx` links and styles, old saved HTML documents) and restored terminal/console output go through `CodeMiniEscape.sanitize`.
- **Inline `onclick` values** built from names the previewed page controls (storage keys, request ids) and from notebook package names are JSON-quoted, then escaped. The preview's object tree escapes keys and values.
- `shield.js` is the first script on the page, before the inline and CDN scripts, and a test pins it. Added a referrer policy, `noopener` on the preview pop-out and an external link, read-only CI permissions and Dependabot.
- New tools: `scripts/sri.js` (add or check Subresource Integrity hashes; needs network and a maintainer run), `scripts/scan-html-sinks.js` (lists unescaped HTML interpolations). New tests: `tests/html-sinks.test.js` (with a per-file ratchet), `tests/hardening.test.js`, `tests/e2e/xss-names.e2e.js` (hostile names across the Explorer, search, tabs and archive tree), `tests/e2e/sanitize.e2e.js` (30 hostile payloads, mutation-stability, legitimate Markdown surviving).

- **Locked files and folders** no longer store their password. A lock is now a random salt plus a PBKDF2-SHA256 verifier (600,000 rounds), and a locked file's text is encrypted with AES-256-GCM, so reading IndexedDB no longer reveals either. Locks made by earlier versions are upgraded automatically when the app loads. Raw and zip downloads skip locked files (the JSON export keeps them encrypted and restores them locked). Items inside a locked folder are not individually encrypted.
- **GitHub token** is no longer kept in plain `localStorage`, and no longer needs My Keys to be unlocked. It is encrypted with a new **device key** (see Shield below) and stored as ciphertext per window (`codemini_git_gh_tokenenc_<window>`). It stays usable after My Keys locks and after a reload. The decrypted token is held in memory while the page is open (a session cache), because Git operations read it synchronously. Older copies migrate on their own: a plain-text token when the page loads, a token in My Keys the next time it is unlocked (the vault copy is then removed, and only after the new copy has been stored and read back). If IndexedDB is unavailable the token falls back to the My Keys vault, as in the previous build. A failed save never destroys a working token. If the device key is lost while the record remains, the record is removed, a notice is shown, and the token has to be added again. Honest limits are in SECURITY.md: the device key protects against copied storage and leaked backups, not against someone using the open browser or script running in the page.
- My Keys still exposes one narrow, named slot for the GitHub token (`getSecret` / `setSecret` / `removeSecret`), now used for the fallback and for moving old tokens out; all other entries remain unreadable by code.
- **"Reset settings"** keeps the encrypted token record, the same way it keeps the vault. (Delete Profile and Wipe Native Data still remove it with the rest of that window's data; the shared device key stays.)
- New: `js/core/file-lock.js`, `tests/file-lock.test.js` (in `npm test`).
- **CodeMini Shield** (`js/core/shield.js`): one shared crypto layer with no UI. Key derivation (PBKDF2-SHA256), AES-256-GCM, random salts and IVs, base64 helpers, record-shape checks and an in-memory key ring now live there, and My Keys and file locks call it instead of carrying their own copies. Shield never unlocks a password-protected item by itself: locked files, locked folders and My Keys still open only with the password you chose, and they never use the device key.
- **Shield device key** (`Shield.device.seal` / `open`): one non-extractable AES-256-GCM key kept in IndexedDB (`codemini_shield`), for secrets with no password of their own (today only the GitHub token). Records are `{ v, iv, ct }`, padded to hide length, and bound to a purpose string (`github-token:<window>`), so a record copied into another window's slot does not open. Two tabs racing to create the key end up sharing one. This is the only part of Shield that touches storage; `tests/shield.test.js` checks that.
- New: `tests/git-token.test.js` (in `npm test`, real `shield.js` and `git.js` against fake storage), `tests/lib/fake-idb.js`, and `tests/e2e/git-token.e2e.js` (real Chromium: real IndexedDB, the key refuses export, reload with My Keys locked, disconnect, lost key, plain-text migration). **Nothing is migrated:** the stored formats are unchanged, and records from before this change open as before (and the reverse, so a rollback loses nothing). `tests/fixtures/legacy-formats.json` holds records written by the old code, and `tests/shield.test.js` (in `npm test`) opens them.
- **Renamed** `js/core/vault.js` to `js/core/my-keys.js` and `tests/vault.test.js` to `tests/my-keys.test.js`. The saved data keeps its names (`codemini_vault_<window>`, `type: "codemini-vault"`), because renaming those would orphan existing vaults. `index.html` and the service worker precache list load `shield.js` right after `app-info.js`, then `my-keys.js`.

## 1.3.1

### My Keys

- **My Keys** (activity menu) is now a real sidebar: an encrypted vault for API keys, tokens and passwords. Header with the title on the left and refresh and close on the right; tabs **Add Keys**, **My Keys** and **Config**.
- **First use** shows a full-sidebar "Create your vault password" screen (not a modal): password plus confirmation, a strength meter, weak and common passwords refused, and an acknowledgement that a forgotten password cannot be recovered. Afterwards a full-sidebar **locked** screen asks for the password every time the vault is opened.
- **Encryption**: everything (names, services, notes, values) is one AES-256-GCM blob, with a key derived from the password by PBKDF2-SHA256 (600,000 rounds, random salt). Only ciphertext is stored (`codemini_vault_<window>`); the password and key are never saved. The stored size is padded so it does not reveal how many keys there are. Each window or profile has its own vault.
- **Locking**: when the sidebar closes (default), after 1, 5, 15, 30 or 60 idle minutes, when switching windows, optionally when the app goes to the background, and on page hide. Five wrong passwords in a row slow further tries. A restored session always comes back locked.
- **My Keys tab**: search, masked values, reveal (hides itself after 10 to 60 seconds), copy, edit and delete with confirmation. **Add Keys**: name, service, type, value (optionally multi-line) and notes.
- **Config tab**: auto-lock time, lock-on-close, lock-on-background, reveal time, lock now, change password (re-encrypts), encrypted backup export and import (merge), plain-language notes on what is and is not protected, and an erase-vault danger zone. "Forgot your password?" leads to a type-ERASE confirmation.
- "Reset settings" in Settings leaves the vault alone; Factory Reset and deleting a profile remove it with the rest of that window's data.
- New: `js/core/vault.js`, `tests/vault.test.js` (in `npm test`), `tests/e2e/keys-vault.e2e.js`. PRIVACY.md and SECURITY.md describe the vault.
- The three on/off options in the Config tab are now the same 40x22 pill switches used in Settings, instead of small native checkboxes.
- Version bumped to 1.3.1 (`package.json`, `app-info.js` and `CACHE_NAME` match).

### Notifications

- **Notification toast**: a notification that arrives while Now Island is closed now shows as a toast in the same corner as the app's other toasts (bottom right on desktop, full width above the status bar on mobile). Source name at the top left (for example "Source Control"), close icon at the top right, the title below it, then the text on one line, truncated. Click it to open the notification in Now Island; the X only dismisses it. - **Source Control**: merge, cherry-pick and rebase conflicts, a rejected saved GitHub token, and failed pushes and pulls. Each clears itself when resolved (conflicts finished, token replaced, next success). Messages go through the token redaction first.

- **Notebooks**: Python or R finishing loading, a package install finishing, and Run All finishing after 15 seconds or more, only when the app is in the background or you moved to another window or profile, and never for a run you stopped.
